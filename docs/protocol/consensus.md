# Retro Boomer V1 consensus

The source selects one profile for every non-genesis block. Existing internal V2/V4 names identify implementation constructions, not successive protocols on this chain. There is no migration from the original Parano1d chain.

The target node requires one source-defined three-class bank; final no-burn artifacts are currently deferred. Small, Large and Native select resource envelopes within the same protocol, including ordinary transactions, proof-native contracts and native finance. All classes use V4 ownership and the same genesis boundary. Class changes must preserve the complete recursive matrix obligations.

The first block extends the exact built-in Retro Boomer genesis. Its origin is derived from the canonical genesis and the new bank; no old terminal or retirement certificate can establish it. The circuit pins the origin block identifier and genesis accumulator, and normal acceptance checks the selected bank and full proof.

Only the primary coinbase is a system mint. Additional coinbases, including the original two-output fund shape, are rejected. The block relation contains no scheduled fund actions, fund recipients, reserved reward share or payout-driven transaction-index shift. The miner subsidy is constrained from the authenticated child height using the same integer halving schedule as native validation.

Coinbase pays exactly the scheduled subsidy plus every paid fee, including the occupancy-dependent state-growth charge; no TAPE fee burn or underclaim is allowed. Fees are transfers, and only subsidy increases supply.

All transaction semantics, value conservation, owner authorization, exact-state roots, transaction roots, PoW and recursive proof checks remain required. Development builds without a pack cannot provide proof acceptance authority; release/embedded-pack builds are currently blocked until genuinely regenerated, authenticated and pinned no-burn matrices are available.

The reconstructed profile is undergoing qualification. Compilation and component tests alone do not establish working end-to-end mining, native finance or synchronization.
